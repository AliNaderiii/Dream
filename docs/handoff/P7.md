# P7 handoff — Reliability, anti-hang, and engine resilience

## What this phase is

Dream grew capability faster than it grew *bounds*. Research loops,
subagents, bridge streams, reminder delivery, and the ledger can each
block. A blocked path that never yields is a hang: the UI spins, a
SQLite lock leaks into a second process, a child sleeps through `/stop`.

P7 adds **`dream/reliability/`** — a reusable toolkit for cancellation,
deadlines, a hung-task watchdog, budgets, backpressure, stream stall
detection, worker supervision, and SQLite helpers. The invariant is one
sentence: **nothing hangs forever**.

This phase is additive. Existing supervision stays where it is (sidecar
restart/backoff, reminders `BEGIN IMMEDIATE`, ledger atomic writes, P4
`CancellationToken`, P1 `research.stop`). The toolkit **calls** those
surfaces; it does not rewrite them.

## Delivered

### `dream/reliability/cancel.py`

`CancelToken` is a composable cooperative flag. Children inherit a
parent's cancel. Linked P4 tokens and research `threading.Event`s are
polled on every check and are themselves signalled when this token
fires. `link_subprocess` sends SIGTERM then SIGKILL. `wait` is hard-
capped at 30 s.

Adapters (do not edit the owners):

- `adapt_agentmodes(CancellationToken)` — P4 `dream.agentmodes.cancel`
- `adapt_research_stop(event)` — P1 `RunContext.cancelled` /
  `ResearchSession.cancel`

### `dream/reliability/deadline.py`

`Deadline.after` / `Deadline.absolute` carry `owner` and `step`.
`DeadlineExceeded` names both. Nested `child(step, budget)` cannot
outlive the parent. `clamp_delay` (2 s) and `clamp_timeout` (120 s)
refuse client `1e9` values.

`Watchdog` runs a callable on a daemon thread (or awaits a coroutine),
fires the token when the deadline expires, and records `cause`.

### `dream/reliability/budget.py`

Per-turn / per-session limits for time, tokens, output bytes, disk,
memory, and money. Exhaustion chooses truncate, skip-with-rationale, or
fail. Every refusal is bilingual (EN + FA, FA stored as `\uXXXX` with a
`# Gloss:`). `attach_ledger` / `consume_ledger_turn` call
`dream.commerce.Ledger`; they do not rewrite it.

### `dream/reliability/backpressure.py`

`BoundedBuffer` / `BoundedList` with drop-oldest, coalesce-same-key, or
reject. The maxlen itself is capped at 10 000.

### `dream/reliability/streams.py` + additive `dream/bridge/streams.py`

`guarded_aiter` keeps **one** pending `__anext__` task. A quiet producer
raises `StreamStalledError`. The bridge module now clamps `delay` and
exposes `stream_with_stall_guard` without breaking existing signatures.

### `dream/reliability/resource.py`

`ResourceSupervisor` tracks threads and subprocesses: idle heartbeat,
stale reaping, restart with the sidecar policy (3 tries, 2/5/10 s),
and a `shutdown` that does not leak FDs or joinable threads.

### `dream/reliability/db.py`

`connect_sqlite` sets `PRAGMA busy_timeout` **before** `journal_mode=WAL`.
`run_transaction` is `BEGIN IMMEDIATE` plus locked-retry backoff.
`claim_delivery` is the per-destination idempotency helper modelled on
`check_due_reminders`. `durable_write` is tmp + fsync + `os.replace`.

### Degradation ladder (`dream/reliability/__init__.py`)

`full → reduced → offline/echo → honest error`. Every step is logged
in English and Persian. There is no silent fifth rung.

## Architecture decisions

1. **Adapt, never rewrite.** P4 and P1 already have stop flags. A second
   flag that those loops do not check would be decoration.
2. **One pending `__anext__`.** `wait_for` on a fresh `__anext__` each
   poll cancels the generator. The stall wrapper keeps the task.
3. **`busy_timeout` before WAL.** The two-process barrier test is the
   proof; the helper encodes the order so owners cannot get it wrong.
4. **Sidecar backoff is the restart policy.** 3 tries, 2/5/10 s. Do not
   invent a fourth flavour.
5. **Honest bilingual exhaustion.** Truncate, skip with a rationale, or
   fail. Never pretend the work finished.
6. **Soak must die on its own.** `SIGALRM` 30 s plus a 25 s soft cap.

## Security posture

Reliability is not a new privilege. Tokens do not bypass the P6 sandbox,
plan gate, or gateway. Public delays are clamped so an RPC cannot hang
the sidecar. Durable writes use the same tmp+fsync+replace pattern as
the ledger. Fail closed on unknown degradation state.
