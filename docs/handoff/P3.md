# P3 handoff — Data Q&A

## Delivered

P3 adds an offline-first, stateful Data Q&A vertical without modifying P1/P2-owned central files.

- `dream/dataqa/`: contracts, bounded readers, Persian-aware discovery/profile, grounded planner, trusted worker/watchdog, quota-bounded SVG charts (line, bar, histogram, box, scatter, and correlation heatmap), and file-backed sessions.
- `dream/bridge/methods_dataqa.py`: auto-discovered `dataqa.*` handlers and streamed ask result.
- `tools/dataqa_probe.py` and `examples/dataqa_demo.py`: independent probe/demo; `cli.py` is untouched.
- `/dataqa`: auto-registered desktop route, typed extension bridge wrapper, deterministic Echo runtime, schema/evidence/chart/audit UI, and eight locale namespaces.
- API/user docs and offline security/state/quality tests.

## Architecture decisions

1. **Plans, not evaluated model code.** The planner produces a closed `QueryPlan`. Its pandas code is audit material only. The trusted worker implements allowed operations directly.
2. **Dependency-free offline path.** CSV/TSV/JSON/JSONL/safe YAML/SQLite use stdlib readers. Optional formats are ranked but honestly marked unavailable. This keeps Echo and Python tests deterministic on the minimal install.
3. **State is bounded and killable.** Sessions persist the latest validated plan, not a live interpreter. Every turn starts a fresh watchdog-controlled process, allowing composition without an unkillable kernel.
4. **Data never becomes instruction context.** Profiling scans cells; execution excludes suspicious rows. Values are never concatenated into prompts or code.
5. **Public paths are relative.** Internal absolute paths remain only in workspace-confined session files. Bridge DTOs expose `relative_path`/`asset_path`.
6. **Owned seams only.** Backend registration uses P0 `methods_<domain>.py`; desktop uses route auto-registration and `createDomainBridgeClient`. Echo routing is isolated in P3's wrapper because the central client is intentionally untouched.

## Security posture

The local worker runs with `python -I`, a reduced environment, pinned cwd, socket denial, process deadline, and POSIX CPU/address-space/file/open-file/process limits. Output is capped and recursively redacted. The result explicitly says networking is off. The local boundary is deliberately labelled weaker than Docker and emits a warning. No model-generated source is executed on the host.

## Owner follow-ups

- Run the live-provider smoke only when credentials and an approved provider are available. The shipped implementation does not require a provider.
- Optional future composition can delegate supported formats/charts to `dream.skills.data_science` when pandas/Docker are installed; do not weaken the stdlib fallback.
- Consider a Docker-specific trusted worker image for stronger isolation while retaining current no-hang behavior.
