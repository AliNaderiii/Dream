# P6 handoff — Agentic security & integrity defense-in-depth

## What this phase is

Dream already had an eight-layer defense-in-depth program (tool-risk floor,
EN+FA injection scanner, sensitive-path refusals, child-env secrecy and
redaction, scopes, approval throttling, constant-time tokens, degraded
autonomous grants, quarantine, blocklist, and a smoke-alarm audit). Between
P1 and P5, Dream grew capability faster than it grew containment: a research
engine that loops, a data-Q&A path that generates and runs analysis code, a
workspace with `!shell` and agent modes, and a provider hub with an optional
credentialed gateway.

P6 adds **L9 — the agentic layer**: five reusable primitives that sit under
those four surfaces, a threat-model revision that names the new assets and
attack paths honestly, and an audit extension that is *proven to fail* when
a control breaks.

Nothing in L1–L8 was rewritten. Every new module **calls** the layer it
depends on.

## Delivered

### `dream/security/agentcode.py` — L9-A, sandbox-only execution

The contract is one sentence: **the host never executes model-generated
code.**

- `preflight_code` **parses** (never evaluates) a program and refuses:
  imports outside a deny-by-default allowlist (`ALLOWED_IMPORTS` is the
  analysis stack plus authority-free stdlib — `os`, `sys`, `socket`,
  `subprocess`, `shutil`, `pickle`, `ctypes` are simply absent);
  `exec`/`eval`/`compile`/`__import__`; object-graph escapes
  (`__globals__`, `__subclasses__`, `__reduce__`, …); and string literals
  naming a path outside the mounted dataset root (absolute, `~`,
  drive-lettered, UNC, `..`).
- `SandboxPolicy` is frozen with `network_enabled=False` and **raises** if a
  caller tries to set it True. It carries wall-clock, memory, CPU, PID,
  disk, and output bounds, all validated.
- `run_agent_code` confines the working directory with symlinks resolved,
  delegates to `DockerSandbox.run_code` with a read-only mount, wraps it in
  an outer deadline, and truncates + redacts the output.
- **Docker unavailable ⇒ refuse.** There is no host-subprocess fallback. The
  bilingual refusal says exactly that.

### `dream/security/codegrounding.py` — L9-B, data as data

L5 guards prose entering context. L9-B guards *values* entering a
**code-generation** context, where the payload has a compiler behind it.

- **Never interpolate.** `as_code_literal` renders inert literals (proven by
  `ast.literal_eval` round-trips in the tests); `as_parameter_block` emits
  JSON the sandbox *loads*, so a hostile value is a string in a dict, never
  a fragment of a statement.
- **Frame as data.** `frame_as_data` wraps content in a fenced, labelled
  block under a bilingual "this is data, not instructions" banner, and
  neutralises any fence the payload itself carries.
- **Reject lookalikes.** `scan_data_payload` calls
  `injection.scan_text` first (shared truth for overrides, hidden Unicode,
  tool-call shapes), then adds codegen detectors: fences, comment smuggling,
  shell/pipe payloads, SQL tampering, credential reads, exfiltration verbs,
  agent-addressing phrasing, and Persian data-poisoning («این دستور را اجرا
  کن», «به کد اضافه کن», «همه فایل‌ها را حذف کن», «کلید را بفرست»,
  «ستون‌ها را نادیده بگیر»).

### `dream/security/planpolicy.py` — L9-C, plan gating

- Approval binds to `plan_digest(kind, steps)` — a SHA-256 over the plan's
  kind and *ordered* steps. Edit, reorder, add or drop a step after approval
  and the digest no longer matches, so the classic **plan swap** refuses.
  Volatile bookkeeping (`status`, `updated_at`) is excluded so a live status
  tick does not invalidate a grant.
- `EXPENSIVE_ACTIONS` (code execution, long runs, network fetch, bulk model
  calls, writes, deletes, shell, provider probes, exports) require approval.
  `DEGRADED_GRANTS` (plan, read, list, summarise, status) do not.
- In `cron` / `single_query` / `autonomous` contexts approval **cannot be
  minted at all**, and every expensive action refuses with `degraded_grant`.
- `ApprovalAttemptLimiter` is a sliding-window throttle where a *refused*
  attempt still costs budget — the cost being defended against is the
  asking, not the granting.
- `authorize_tool` runs the plan gate, then delegates the tool verdict to
  `ApprovalPolicy.allows`. The L3 floor still precedes every gate, and the
  plan gate can only ever **add** a refusal, never rescue a denial.

### `dream/security/authenticity.py` — L9-D, artifacts and claims

- `RunFingerprint` hashes the code text, every input file's bytes, the
  parameter block, the run id, and the tool into one `run_hash`. An input
  that cannot be read is recorded as `unreadable` rather than skipped, so an
  incomplete lineage is *visible* instead of implied.
- `seal_artifact` binds an artifact's own SHA-256 to the run hash, records
  it through `ProvenanceTracker` (already hash-chained and value-scanned)
  and links a sidecar through `ArtifactManager`. `verify_artifact` re-hashes
  on disk and reports honestly when the file changed.
- `verify_claims` extracts every number from prose — Persian and
  Arabic-Indic digits, Persian decimal/thousands marks, ASCII separators —
  skips structural references ("section 3", «جدول ۴»), and refuses any
  number no computed value grounds, allowing sane rounding and
  fraction/percent equivalence.

### `dream/security/providergateway.py` — L9-E, credentials and egress

- Tokens are per **tool** and per **scope** (`read` | `use`). There is no
  wildcard tool and no `admin` scope; `mint_token` refuses both, plus
  unbounded lifetimes. Only a SHA-256 digest is retained — the plaintext
  exists once, at mint time.
- Verification is constant-time across every candidate (no early exit).
  `rotate` replaces the secret and keeps the grant; `revoke` is immediate.
- `safe_snapshot` runs the L6 value scanner **and then** drops any field
  whose *name* implies a secret, so a field added later cannot leak by
  omission. `redact_headers` blanks every credential-bearing header.
- `probe_runtime` refuses unknown runtimes, endpoints that are not the
  configured one, non-HTTP schemes, credentials in the URL, crafted paths,
  and non-loopback hosts. Redirects are off, the read is capped at 64 KiB,
  the timeout is clamped to 5 s, and **no credential header is ever sent**.

### Audit, tests, docs

- `tools/security_audit.py` gained L9-A…L9-E sections and a per-section
  guard so a section that *crashes* is reported as a finding rather than
  taking the tool down.
- `tests/test_sec_agentic_audit.py` breaks each control in a subprocess
  across **19 sabotage scenarios** and asserts the audit exits 1 **and names
  the right layer** — plus a baseline check that the pre-P6 L3 alarm still
  fires.
- `docs/security/threat-model.md` → v2.0: five new assets (A9–A13), four new
  personas (P7–P10), the agentic path added to the trust-boundary diagram,
  a full §4 L9 section, an updated layer map, and honest residual risks.
- `docs/security/audit-report.md` gained a P6 addendum.
- `tools/sec_agentic_probe.py`: an offline diagnostic that shows what the
  layer does to a specific payload, plan, claim, or endpoint.

## Architecture decisions

1. **Call, never rewrite.** Each module depends on an existing layer through
   its public API: `ApprovalPolicy` for tool risk, `injection.scan_text` for
   prose, `DockerSandbox` for isolation, `provenance` for lineage,
   `secrets.redact_*` for value scanning, `providerhubs` for gateway state.
   The forbidden-import rule is asserted mechanically in
   `test_sec_agentic_integration.py`.

2. **Refuse rather than degrade — but only where the input warrants it.**
   L9-A refuses when Docker is missing. The pre-existing data-QA executor
   degrades to a guarded local subprocess and says so. That is not an
   inconsistency: the executor runs a *deterministic plan the planner built*,
   while L9-A runs *a program a model composed*. Different provenance,
   different posture.

3. **Structure first, heuristics second.** L9-B's real defense is that
   values travel as JSON parameters, not as interpolated text. The EN+FA
   scanner is depth on top of that, which is why a novel phrasing slipping
   the scanner is survivable: the payload is still a string, and the program
   consuming it still has to clear L9-A.

4. **Fail closed on the unknown.** An action in neither `EXPENSIVE_ACTIONS`
   nor `DEGRADED_GRANTS` refuses with `unknown_action`. A new capability that
   nobody classified is denied by default rather than allowed by omission.

5. **Approval binds to content, not to an id.** Anything else makes the plan
   swap free.

6. **Prove the alarm, not just the control.** Every control has a test that
   it works *and* a sabotage scenario proving the audit catches it breaking.
   A smoke alarm nobody has ever tested is decoration.

## Security posture

Host never executes model-generated code (asserted mechanically over the
whole `dream/security/` package). Network is off in the sandbox and not
configurable. Every sandbox and probe path carries a timeout; no unbounded
`read()`. Gateway probes carry no credentials, follow no redirects, and
reach only configured loopback endpoints. Every refusal is bilingual
(EN + FA). Test fixtures use broken shapes (`sk_EXAMPLE_not_a_real_key`), so
no `sk-` / `ghp_` / `AKIA` shape exists in a tracked file.

## Owner follow-ups

1. **Wire the call sites.** P6 owns the primitives; `dream/research/**`,
   `dream/dataqa/**`, `dream/workspace/**`, `dream/agentmodes/**` and the
   bridge method modules are outside its change surface. Routing those
   surfaces through `PlanGate` and `seal_artifact` is the natural next slice
   and is recorded as residual risk in the threat model rather than implied
   as done.
2. **Apply the CI patch.** `docs/handoff/sec-agentic-audit.patch` (Path B)
   adds the sabotage suite and the probe as named CI steps. Apply
   `sec-audit.patch` first if it has not been applied.
3. **Live Docker smoke.** The sandbox battery is hermetic (a
   `DockerSandbox` double). A real `docker run` smoke against L9-A is
   owner-run, as is any live vLLM/SGLang/llama.cpp/LM Studio probe.
