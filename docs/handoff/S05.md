## What shipped

The first honest desktop surfaces for plan, usage, and model route, wired to
the existing Python kernel (`dream/commerce.py`, `dream/router.py`) through
three read-only bridge RPCs, with a deterministic echo fallback for browser
dev / vitest.

1. **Settings → General gains a "Plan & usage" section** (`BillingSummary`):
   - plan name in FA and EN (e.g. «محلی (Local)»), sourced from `commerce.py`;
   - quota period (per day / per month / per year / unlimited);
   - turns used / limit for the current window — rendered as ∞
     ("Unlimited turns") when no ledger is attached (the `local` plan);
   - price: `0` renders as localised "Free"; anything else renders the
     `TBD after cost measurement` note. A numeric IRR/toman amount is never
     rendered for a paid plan;
   - resolved model route (hosted / ollama / byok / echo) with the exact
     `sentence_en`/`sentence_fa` privacy sentence from `dream/router.py`, and
     a "Prompts leave this machine" / "Prompts never leave this machine"
     badge;
   - a disabled **"Upgrade (coming)"** button — no Zarinpal, no checkout.
2. **Dashboard gains a first-run card** (`FirstRunCard`): "Works offline — no
   account needed", the offline echo engine line, an Ollama offer ("still
   never leave your machine"), and BYOK presented as optional with the
   explicit "prompts then leave this machine to that provider" sentence, plus
   the live current-route line.
3. **Three new bridge RPCs, appended only** (`dream/bridge/methods.py`, no
   reformatting of the file):
   - `commerce.plan` — active plan, period, honest price, limits,
     `ledger_attached`;
   - `commerce.usage` — used / limit / remaining for the current window,
     `unlimited: true` when no ledger is attached;
   - `route.resolve` — the resolved route and its privacy sentences, identical
     to `dream --route`.
   The RPCs are thin serialisers over `dream.commerce` / `dream.router`;
   pricing policy stays in `commerce.py` (never forked).
4. **Deterministic echo fallback** (`apps/desktop/src/lib/bridge/echo-commerce.ts`)
   so the screens work in `npm run dev` and vitest with no sidecar. The echo
   transport *is* the offline backend, so it honestly reports the `local`
   plan and the `echo` route.
5. **i18n**: new keys added only through
   `apps/desktop/scripts/generate-locales.mjs` — `settings.billing.*` and
   `common.firstRun.*` — Persian filled carefully, all 8 languages keep
   identical key trees (generator's drift check passes: 282 keys × 8).
6. **Docs**: `docs/bridge/protocol.md` gains §3.14 documenting the three RPCs.
