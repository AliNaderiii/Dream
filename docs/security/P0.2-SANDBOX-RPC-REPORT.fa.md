## روش و نقش‌ها

ابزار subagent موجود نبود. همهٔ بررسی‌ها و پیاده‌سازی توسط همین agent انجام شد؛
پنج پاسِ نقش‌محور جایگزین تحلیل موازی شدند، **نه پنج بازبین مستقل انسانی/عامل مستقل**:

1. **Bridge/RPC:** dispatch واقعی هر سه متد در `BridgeMethods.handlers` بررسی شد.
   Code UI فقط code/timeout می‌فرستد؛ caller مشروعی نیاز به workspace یا ID انتخابی ندارد.
   package validation پیش از `_require_sandbox` قرار گرفت؛ آرگومان‌های ناشناخته رد می‌شوند.
2. **Container/security:** notebook قبلاً parent پوشهٔ منبع را mount می‌کرد؛ اکنون فقط
   staging تازه mount می‌شود. `runs` symlink، workspace موجود و aliasها رد می‌شوند.
   reset حین اجرای زنده اکنون `busy` است، نه حذف authority اجرای در حال کار.
3. **Python packaging:** parser اختیاری موجود نبود و dependency تازه مجاز نبود؛ grammar
   کوچک و صریح standard-library نوشته شد. Python و R هر دو JSON exec-form RUN دارند.
4. **QA:** ۱۷ تست unittest با چندین subcase، روی registered handlers واقعی و IO جعلی
   Docker؛ پوشش argv builder واقعی notebook نیز وجود دارد. این‌ها تست kernel نیستند.
5. **پاس بازبینی چالشی/مسیر جایگزین:** validation پایین‌دستی install نیز تست شد؛
   overwrite از طریق symlink stdout، انتخاب workspace موجود، replay و symlink پس از mkdir
   بررسی شدند. یک تغییر ناخواستهٔ exception tuple در متدهای جداگانهٔ `notebook.*` در diff
   شناسایی و کاملاً بازگردانده شد؛ این patch آن مسیرها را تغییر نمی‌دهد.

ترتیب کار: inspect اسناد audit و source/tests → threat model → طرح → پیاده‌سازی →
focused tests → رفع failureها → تلاش برای broader verification → پاس نهایی diff و مستندات.

## زنجیره‌های فعال و root cause

### F1

`Code UI → bridge.js → Tauri/stdin JSON-RPC → BridgeMethods.handlers['sandbox.run_code']
→ sandbox_run_code → CodeExecutionRequest.from_params → CodeExecutionRuntime.run
→ workspace_for → DockerSandbox.run_code → _exec_in_container`.

علت: workspace صریح فقط تا sandbox root محصور بود و regex ID حتی `.`/`..` را
می‌پذیرفت؛ run root/cross-run قابل انتخاب بود و mkdir پیش از کنترل نهایی انجام می‌شد.

اصلاح: RPC فیلدهای `workspace` و `execution_id` را با `removed_field` رد می‌کند، حتی null.
ID با UUID4 کامل تولید می‌شود؛ workspace فقط `root/runs/<id>`، با mkdir انحصاری و
mode 0700 ساخته می‌شود. check قبل و بعد از ایجاد، رد symlink و existing directory،
owner request-object و منع replay اضافه شد. Artifact containment به خود run محدود شد.
Overflow از exclusive create استفاده می‌کند. reset parent symlink را دنبال نمی‌کند و
حین live run authority را پاک نمی‌کند.

### F3

`JSON-RPC → BridgeMethods.handlers['sandbox.run_notebook'] → sandbox_run_notebook
→ DockerSandbox.run_notebook → _exec_in_container → _run_docker_cmd_with_output`.

علت: mount مستقیم `nb_path.parent` و interpolation filename در `/bin/sh -c`؛ برای R
علاوه بر shell، filename وارد expression نیز می‌شد.

اصلاح: root فقط از `DREAM_NOTEBOOK_ROOT` یا constructor قابل اعتماد operator؛ بدون root
درخواست denied است. source باید canonical و داخل root، regular `.ipynb` با nbformat 4
و حداکثر 10 MB باشد. directory-fd walk و `O_NOFOLLOW` جلوی دنبال کردن symlink هنگام read
را می‌گیرد؛ پلتفرم بدون قابلیت امن fail-closed می‌شود. فقط کپی `input.ipynb` در staging
تازه `data_dir/notebook-runs/nb-*` mount می‌شود. هیچ write-back وجود ندارد. هر دو kernel
مجاز `python3`/`ir` با argv ثابت Jupyter اجرا می‌شوند؛ timeout عدد صحیح 1..600 است.
Spaces/quotes/semicolon/`$()`/backtick به‌عنوان دادهٔ filename مجازند؛ newline/control رد می‌شود.

### F5

`JSON-RPC → BridgeMethods.handlers['sandbox.install_packages'] → sandbox_install_packages
→ validate_packages → DockerSandbox.install_packages → validate_packages دوباره
→ Dockerfile JSON RUN → docker build`.

علت: list فقط از نظر nonempty بودن بررسی می‌شد؛ raw strings به shell-form RUN وارد
می‌شدند، build شبکه داشت و mapping عمومی class پس از build تغییر می‌کرد.

اصلاح: list با 1..64 رشتهٔ ASCII، هر کدام 1..128 کاراکتر؛ Python name یا `name==version`
در subset مستند از PEP 440 و R name محدود. options/direct URL/markers/extras/ranges و
metacharacters رد می‌شوند. `RUN` فقط JSON argv است؛ Python `pip --isolated ... -- specs`
و R expression تنها از names ازپیش‌اعتبارسنجی‌شده ساخته می‌شود. gate نصب پیش‌فرض بسته است؛
تنها trusted constructor با `package_install_approved=True` به‌طور صریح network و mutation
را تأیید می‌کند. هیچ flag در RPC نمی‌تواند آن را باز کند. built-in bridge این مجوز را
فعال نمی‌کند. build با `--network=default` و env فقط PATH/HOME تازه انجام می‌شود؛ نه secret،
نه SSH، نه credential/proxy forwarding. tag یکتا؛ تغییر image mapping فقط در همان instance
و پس از موفقیت. rejected input اصلاً build directory یا image نمی‌سازد.

## ریسک، migration، rollback و follow-up

- این boundary در برابر RPC/cell/package untrusted است، نه operator یا process متخاصم
  با همان host UID/root که می‌تواند والدهای mount را در race عوض کند. owner-only root و
  recheck ریسک race را کم می‌کنند، تضمین transaction با Docker daemon نیستند.
- default images لزوماً Jupyter/nbconvert یا `ir` ندارند. برای notebook باید image مناسب
  از قبل provision شود؛ این patch خودکار dependency نصب نمی‌کند. اجرای زندهٔ این images
  بررسی نشده است. safe notebook source opening در پلتفرم بدون dir_fd fail-closed است.
- staging موفق حفظ می‌شود؛ retention/پاک‌سازی operator لازم است. Code reset فقط Code runs
  را پاک می‌کند. حذف image/tag یا build cache یک lifecycle جدا و خارج این patch است.
- package-install approval یک مجوز operator در سطح instance است، نه interactive approval
  برای هر درخواست. stock bridge نصب را بسته نگه می‌دارد. اگر operator آن را باز کند، package
  build همچنان کد third-party با شبکه در builder اجرا می‌کند؛ daemon اختصاصی توصیه می‌شود.
  cancel/timeout ممکن است build/cache سمت daemon باقی بگذارد؛ image mapping فقط با موفقیت عوض می‌شود.
- callers باید `workspace`/`execution_id` را از Code request حذف کنند؛ response ID را برای cancel
  به کار ببرند. caller مشروع production نیازمند ID/workspace انتخابی در repo پیدا نشد.
- notebook caller باید source را زیر root مجاز قرار دهد؛ نتیجه دیگر در کنار source نوشته نمی‌شود.
  output_files به staging اشاره می‌کند. kernel و tooling باید از قبل فراهم باشند.
- نصب بستهٔ قبلاً آزاد اکنون پیش‌فرض denied است؛ URLs/options/ranges دیگر supported نیستند.
  operator نباید approval را از params RPC به constructor منتقل کند.
- rollback: این فایل‌های patch را به baseline بازگردانید؛ migration پایگاه داده لازم نیست.
  rollback امنیت F1/F3/F5 را دوباره باز می‌کند و توصیه نمی‌شود. frontend contract تغییر نکرده است؛
  rollback frontend لازم نیست. هیچ دستور rollback مخرب در این نوبت اجرا نشده است.
- **F6: MCP stdio process trust** بدون تغییر، follow-up مستقل.
- **D3: image digest policy و live-container CI suite** بدون تغییر، follow-up مستقل.
- پیش از merge: روی محیط آماده، focused/full pytest، Ruff، frontend tests و safe live Docker
  integration را اجرا کنید؛ این report آن‌ها را موفق اعلام نمی‌کند.
