# P5 handoff — Providers UI (local runtimes & tool gateway)

## Delivered (this slice)

The `/providers` page keeps its existing catalog editor and gains a P5 seam:

- `apps/desktop/src/lib/bridge/providerhubs.ts` + `echo-providerhubs.ts` — typed wrappers, echo when `transportKind === 'echo'`.
- `apps/desktop/src/components/providerhubs/**` — local runtime cards, searchable catalog, optional tool gateway, and “why aren’t tool calls firing?” diagnostics.
- `apps/desktop/src/routes/providers.tsx` — mounts `ProviderHubsPanel` without rewriting the existing editor/cards.
- `apps/desktop/src/locales/<lang>/providerhubs.json` — all eight locales, including complete Persian.
- `docs/dev/api/providerhubs-rpc.md` — RPC contract for the sidecar family.

## Invariants kept

- Recommended path is local Ollama. No cloud key is required to run locally.
- Router priority remains hosted → aval → ollama → byok → echo.
- No invented prices. Cost is described as local, bring-your-own-key, or optional subscription.
- Credentials are never shown. Echo probes set `secrets_sent: false`.
- Generic fallback parser is flagged as reduced reliability.
- Forbidden central files (`App.tsx`, `client.ts`, `common.json`, route-registry tests, and the existing providers editor internals) were not rewritten.

## Owner follow-ups

- Live vLLM / SGLang / llama.cpp / LM Studio smoke stays owner-run when those stacks are installed. CI uses the echo matrix.
- Sidecar handlers (`dream/providerhubs/**`, `dream/bridge/methods_providerhubs.py`) should implement the same method names and DTO fields.

## Sidecar (follow-up)

`dream/providerhubs/**` and `dream/bridge/methods_providerhubs.py` now implement the same eleven `providerhubs.*` methods the desktop wrapper already calls. Adapters are hermetic in CI via a mock compatible endpoint. Probes are bounded and send no secrets. The optional tool gateway stays off by default.

See `P5-GATES.md` for observed command output.
