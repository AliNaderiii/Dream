# S12 — Windows installer that actually attaches + sidecar finds Python

**Status: Gate G12 met in code; one push step is owner-run.** All S12 code,
docs and version bumps are on the PR branch. The
`.github/workflows/desktop-release.yml` rewrite is committed locally as a
follow-up commit and handed to the owner as `docs/handoff/S12-workflow.patch`
because the session's GitHub App is missing the `workflows` permission needed
to push workflow files (see `docs/handoff/S12-BLOCKED.md` for the one-line
owner procedure). The Tauri sidecar now discovers a Python interpreter on
Windows instead of assuming `python3`, and once the owner pushes the workflow
commit, `desktop-release.yml` will publish (not draft) the GitHub Release for
every `v*` tag with the unsigned Windows NSIS installer attached, failing the
job if the release ends up with no installers. The desktop shell version is
bumped to 0.3.0, and the docs describe both honest Windows paths: `run.bat`
today, and the Tauri installer (still needs a local Python kernel) after the
`v0.3.0` tag.

## Why this session existed

- GitHub Releases `v0.2.0` and `v0.2.1` have **zero assets**. There was no
  `.exe` for a Windows user to download.
- The Desktop Release run for tag `v0.2.1` (commit `ded789f`) failed inside
  `tauri build` with TypeScript parse errors — the old dropdown-menu bug that
  S06 already fixed on main. Current main desktop CI typecheck is green.
- `.github/workflows/desktop-release.yml` used `tauri-apps/tauri-action` with
  `releaseDraft: true`, so even a green build would have left a draft release
  the public never sees.
- The sidecar spawn assumed `python3`; on Windows the interpreter is usually
  `python` or `py`, so an installed `.exe` that cannot start the sidecar would
  be a dead window.

## What changed

### Sidecar — `apps/desktop/src-tauri/src/bridge/process.rs`

- `SidecarConfig.python` is now an **ordered list of interpreter candidates**
  instead of a single executable.
- `DREAM_SIDECAR_PYTHON` remains a hard override: when set (and non-empty) it
  is the **only** candidate. `DREAM_SIDECAR_MODULE` is unchanged.
- When the override is unset, candidates are tried in order: `python`, `py`
  (the Windows launcher), `python3`. Spawn is still `<exe> -u -m dream.bridge`
  — the module and the `-u` unbuffered flag are unchanged.
- Discovery is smarter than "spawn or skip": a candidate that **exits before
  completing the `DREAM-PROTOCOL:` handshake** (a Windows Store `python.exe`
  stub, Python 2, or a Python without `dream` installed) is skipped in favour
  of the next candidate within the same attempt. Only an instance that
  completed the handshake counts as a real sidecar, so its death takes the
  existing restart/backoff path (max 3 restarts, 2/5/10 s) and a pre-handshake
  exit does not burn retries on a useless interpreter.
- If no candidate can start, the existing flow still ends in
  `ConnectionState::Disconnected`, and a clear reason is logged in **English
  and Persian**: Python 3.10+ with the `dream` package installed
  (`pip install -e .` from the repository root) is required. The Persian text
  is UTF-8 in the Rust source (allowed; only `dream/*.py` strings stay
  `\u`-escaped).
- Framing, dispatcher, heartbeat, and backoff logic are untouched;
  `supervise_reader` only gained a `reached_ready` bool return.
- New unit tests in `process.rs` (4): default candidate order, hard override
  replaces the list, fake command order (python/py fail → python3 wins, walk
  stops in order), and the all-fail path. Tests inject a fake environment
  reader and a fake probe — no real processes, no `set_var`, so they are safe
  in parallel and platform-agnostic (they run on the Linux/macOS cargo-test
  jobs; the Windows job skips cargo tests per the existing ComCtl32 note).

### Release — `.github/workflows/desktop-release.yml`

- Tag pushes (`v*`) now run tauri-action with **`releaseDraft: false`** — the
  release is created **published**, with the bundles attached as assets. This
  is the fix for "owners never see files".
- A pre-step publishes any **stale draft** release for the tag (tauri-action
  looks up releases by tag with `getReleaseByTag`, which 404s on drafts and
  would otherwise make the create call fail). No release yet → no-op.
- `releaseBody` is an honest note: installer is the UI shell only (no bundled
  Python), unsigned (SmartScreen may warn), WebView2 may download, `run.bat`
  is the no-installer path.
- The Windows job runs **without** `WINDOWS_CERTIFICATE` — unsigned is the
  expected path; the cert is still picked up when the owner adds it.
- Updater keys stay optional: `includeUpdaterJson` is only enabled when
  `TAURI_SIGNING_PRIVATE_KEY` **and** its password exist. With
  `createUpdaterArtifacts: false` in `tauri.conf.json`, no `.sig` files exist
  and the action skips `latest.json` gracefully — the job never fails for
  missing updater keys.
- Gate steps were added: (1) the Windows job fails if no `*-setup.exe` was
  produced under `target/release/bundle/nsis`; (2) every tag-run job verifies
  with `gh release view` that the tag's release actually has its platform's
  installers attached — the release can never be silently empty again.
- `workflow_dispatch` now builds installers and uploads them as CI artifacts
  **only** (the old unused `publish` input was removed — a dispatch run has no
  tag to publish to). Linux job unchanged; macOS stays excluded.

### Version honesty

- `apps/desktop/package.json`, `apps/desktop/src-tauri/tauri.conf.json` (and
  the two version fields of `package-lock.json`) bumped **0.2.0 → 0.3.0**.
  `Cargo.toml`, `pyproject.toml`, and `dream/__init__.py` were left untouched
  per the session's isolation list.
- `CHANGELOG.md` Unreleased gained the S12 entry and a Changed bullet; the
  entry records that 0.2.0/0.2.1 releases had no assets and 0.3.0 is the first
  intended Windows NSIS from current main, unsigned.

### Docs

- `README.md` Windows section now has two true paths: **run.bat today**
  (clone + Ollama), and the **Tauri installer after the `v0.3.0` tag**
  (unsigned NSIS, still needs Python 3.10+ on PATH with `pip install -e .`,
  WebView2 may download, SmartScreen warning expected).
- `docs/user/quick-start.md` mirrors both paths with the exact commands.
- `apps/desktop/README.md` Updater section: one clarifying paragraph — updater

- `docs/handoff/S12.md` (this file).

## What did not change

- `dream/*.py` is untouched: no commerce.py prices, no invented IRR, no agent
  loop change, no council auto-start, no Zarinpal/Telegram/Bale/Eitaa work.
- No CPython is bundled; `tauri.conf.json` `externalBin`/`resources` stay
  empty — the installer is honestly the UI shell.
- No Authenticode secrets, no Apple signing, macOS stays excluded.
- Framing, dispatcher, heartbeat, restart/backoff and the bridge command
  surface are unchanged. No frontend TypeScript was touched.
