# S10 — Opt-in three-role council (proposer / critic / judge)

**Status: Gate G10 met.** An opt-in council runs exactly three sequential
children — proposer → critic → judge — as one `SubAgentManager` pipeline, and
the judge's result is the winner. It starts only when the user asks
(`council.run` or `dream --council "topic"`); the demo, the default chat send
path and a normal `subagent.spawn` never start one. The echo path is
deterministic and offline, a metered plan consumes the council's three member
turns exactly once, dangerous tools stay fail-closed, and the desktop
Subagents page renders a three-column council widget with a winner strip.

## What changed

### Kernel — `dream/council.py` (new)

- `CouncilSpec {prompt, proposer?, critic?, judge?}` and
  `run_council(manager, spec) -> CouncilResult`, reusing
  `SubAgentManager.spawn_pipeline` — no second runtime. Each stage's result
  is carried into the next stage's context by the existing pipeline driver.
- Roles are fixed and always three: proposer (first answer, concrete),
  critic (holes, false assumptions, risk — does not rewrite the whole
  answer), judge (picks or synthesises ONE final answer; the judge's result
  is the winner). `get_council(manager, council_id)` re-derives live member
  statuses and exposes the winner once the judge completes; before that the
  snapshot reports `winner=None` — never a silent fake winner.
- Opt-in only. Defaults keep the first run offline-green: every member
  defaults to `model_provider="echo"`, `allow_dangerous=False`, and the tool
  grant is `DEFAULT_TOOL_GRANT` only — a council child never receives
  filesystem, shell, network or mail tools. An unknown provider refuses the
  whole council before any turn is consumed or child spawned; an empty
  topic/prompt raises `ValueError` before anything else.
- Privacy: each `CouncilMember` exposes `leaves_machine` (echo/ollama stay
  local; `openai`, `aval`, `avalai` leave; anything else falls back to
  `dream.router.resolve_route()`). `leaves_machine_any` and the English and
  Persian result sentences state it honestly (new Persian in `dream/*.py` is
  `\u`-escaped per M16).

### Quota — one `consume(amount=3)`, never per child turn

- When a ledger is attached (same rule as `Dream`: `DREAM_PLAN` not `local`
  or `DREAM_LEDGER` set), the council consumes its member turns **once**,
  atomically, before spawn: `Ledger.consume(amount=3)`. `Ledger.consume`
  gained an additive `amount` parameter (default 1 — prices, periods and
  plan ids are untouched); the whole batch is checked against the window
  limit before any entry is appended, so a refusal never leaves a partial
  batch behind.
- A refused council (quota exhausted, corrupt or misconfigured ledger)
  spawns nothing and returns the ledger's Persian reply in the result's
  `refusal` / `sentence_fa`. The local unlimited plan consumes nothing and
  needs no ledger file.
- Children cannot double-count: `build_child_tools` now takes an optional
  `ledger` and always overrides the env-attached ledger (`Dream.__init__`
  would otherwise attach one from the environment), so a child turn is a
  quota no-op. `DEFAULT_TOOL_GRANT` is unchanged.

### `build_backend` — `aval` / `avalai` (the only `dream/agent.py` change)

- `build_backend("aval")` / `build_backend("avalai")` now return an
  `OpenAIBackend` with base `OPENAI_BASE_URL` or `https://api.avalai.ir/v1`
  and key `OPENAI_API_KEY` or `AVALAI_API_KEY` (the Aval name is read via a
  literal `os.environ.get("AVALAI_API_KEY")`, satisfying M23). This makes
  S09's documented `DREAM_BACKEND=aval` actually constructible and lets
  council members pick Aval. No chat, extraction, reminder or approval code
  was touched; other catalog kinds stay out of scope.

### Bridge — `dream/bridge/methods.py` (append only)

- `council.run {prompt, proposer?, critic?, judge?}` → `{council_id,
  pipeline_id, members, winner, turns_consumed, leaves_machine_any,
  sentence_en, sentence_fa}` (plus `refusal` when the ledger refused).
- `council.get {council_id}` → the same shape with live member statuses and
  the winner. Unknown council id → `INVALID_PARAMS`.
- The members are real pipeline stages: `subagent.list` / `subagent.get` /
  `subagent.logs` work on every `subagent_id`, and `subagent.list` filters
  by the council's `pipeline_id`. Protocol documented in
  `docs/bridge/protocol.md` §3.16 (append).

### CLI — `cli.py` (append only)

- `dream --council "topic"` runs an offline echo council to completion and
  prints the three role excerpts, the winner, and both sentences. `--demo`
  never calls it (test pins that `run_demo` cannot even import
  `dream.council`). No `/council` command was added to Telegram.

### Desktop — Subagents page (no chat rewrite)

- A "Council review" action (header button) opens a small dialog that takes
  one topic and calls `council.run` directly; members default to echo.
- A three-column council widget replaces the plain detail pane when the
  selected child belongs to a council: each column shows the role name,
  provider/model, the local-vs-leaves-machine badge, the live status, and a
  result excerpt; a winner strip (with the English and Persian sentences)
  appears once the judge completes.
- The echo transport mirrors the sidecar (`council.run` / `council.get` in
  `echo-subagents.ts`, dispatching from `client.ts`), so `npm run dev` and
  vitest exercise the widget without a sidecar.
- All new copy went through `generate-locales.mjs` only (8 identical key
  trees, then regenerated); `npx tsc --noEmit`, `npm run format` and
  `npm run format:check` are green. `pane.tsx` was not touched.

### Tests

- New `tests/test_council.py` (24 tests): echo council order and winner,
  empty-topic refusal, unknown-provider refusal before spawn, default-grant
  only + fail-closed dangerous grant, `leaves_machine` flags, `urlopen`
  monkeypatch (echo council never opens a connection), metered
  `consume(amount=3)` exactly once with `used` rising by 3, exhausted-quota
  Persian refusal with nothing appended, local plan consuming nothing and
  creating no ledger file, `build_backend("aval"/"avalai")` pointed at
  `api.avalai.ir`, and `--demo`/`run_demo` never importing or running a
  council.
- `tests/test_bridge_subagent_schedule.py`: six new `council.*` RPC tests
  plus the new methods in the routable-set pin.
- `tests/test_subagents.py`: child ledger is detached even under a metered
  plan. Existing suites stay green: full pytest **1748 passed, 11 skipped**;
  desktop vitest **345 passed**.
