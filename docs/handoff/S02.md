## What shipped

`load_data` (and the profiling that follows) now reads the files Iranian
companies actually send, without a new DeepAnalyze and without touching
chart/report PDF layout.

1. **Encoding sniff (host, stdlib).** CSV/TSV files are sniffed from a
   64 KiB sample: UTF-8, UTF-8 with BOM (`utf-8-sig`), or Windows
   Arabic/Persian (`cp1256`). The name is stored on `DatasetRecord` and
   passed into the sandbox via `_params.json` so `pd.read_csv` and the
   chunked profiler use the same codec. The source copy stays byte-identical
   to the upload.
2. **Persian digits (sandbox).** Before numeric coerce, Persian and
   Arabic-Indic digits become Latin digits; a column is promoted to numeric
   only when every non-blank cell converts. Profile fixtures still agree to
   1e-9.
3. **Header matching.** Arabic yeh/kaf vs Farsi yeh/keheh are folded with
   the existing `normalize_fa`. **Displayed headers are not rewritten** —
   the file's spelling is what the registry, preview, and profile show.
   Exact match wins; a folded hit returns the displayed name.
4. **Caps unchanged.** 500 MB ingest hard cap; files over 100 MB still
   profile via chunked aggregation (now with encoding + digit fold).
5. **Fixtures.** `examples/iranian-sales-cp1256.csv` is real cp1256 bytes
   (not valid UTF-8). `examples/iranian-sales-utf8-sig.csv` is UTF-8 with
   BOM and Persian digits in numeric cells.

## Design decisions worth knowing

- **Display is not rewritten.** A cp1256 file that spells `تاريخ` (Arabic
  yeh) keeps that header in the registry and the preview. A request that
  uses `تاریخ` (Farsi yeh) resolves to the displayed name via
  `normalize_fa`. Documented in `docs/architecture/data-science.md` §6.
- **No pandas on the host.** Sniff and header fold are stdlib
  (`dream.memory.normalize_fa`). Digit folding is inlined in the generated
  prelude because the sandbox runs with `python -I` and cannot import
  `dream`.
- **Encoding lives on the record**, not as a transcode of the stored
  source, so a 500 MB cp1256 file is never decoded on the host. After
  `clean_data`, `cleaned.csv` is UTF-8 and `record.encoding` follows.
- **Office headers** (Persian letters, spaces, light punctuation) are
  accepted for column references; `; / " '` and friends are still
  refused, so the G9 injection denylist stays closed.
