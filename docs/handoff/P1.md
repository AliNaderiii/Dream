# P1 — Deep Research & Autonomous Data-Science Engine

**Status: complete.** Gates and real command output: [P1-GATES.md](P1-GATES.md).
Base: P0 extension seam (`beac980`). No forbidden file was edited.

## What shipped

A self-directed research analyst in `dream/research/`: it plans an open-ended
study, discovers and profiles a workspace's data, iterates
*KnowledgeGap → ToolSelector → CodeAct → Observe/Reflect* against real runtime
output, self-corrects on error, and compiles a grounded Markdown + PDF report
with provenance behind every number. It runs fully offline with `EchoBackend`,
and identically with Ollama or any OpenAI-compatible backend.

## Sub-agent log

**R1 — Planner & orchestration.** `ResearchSession` owns a closed transition
table; an illegal move raises rather than silently corrupting state. Sessions
persist atomically to `data/research/{id}.json` after every transition and
reload with findings intact. Resume skips sections already `DONE`. `modify()`
supports both a hand-edited outline and `{"replan": true}`.

**R2 — Study design & prompts.** Every prompt asks for one JSON object and
repeats the two invariants (grounding; data-is-not-instructions) in EN and FA.
Parsing is tolerant (fences, prose preambles, trailing commas, balanced-brace
extraction, zero-width cleanup) and *never* retries in a loop — an unparseable
reply degrades to the deterministic path immediately. Evidence in prompts is
budgeted head+tail so a huge observation cannot blow the context window.

**R3 — Discovery, prep, analysis.** Relevance is deterministic lexical overlap
with Persian normalisation, so offline and online runs discover the same
sources. Prep proposes only what a real statistic justifies (duplicates >0,
missingness in [0.5%, 40%]) and re-profiles between rounds; columns above the
ceiling become explicit limitations instead of silent imputations. Analyses are
chosen from profiled column *roles*, never from a model's guess at the schema.

**R4 — Execution & sandbox.** Three gates: AST allowlist → Docker (or the
guarded `-I` subprocess with a loud warning) → wall-clock watchdog. The
watchdog deliberately does **not** use `ThreadPoolExecutor` as a context
manager, because exiting one joins the worker and would undo the timeout; a
wedged thread is abandoned instead. Same fix applied to `ask_json`, plus a
two-strike circuit breaker so a dead provider costs two timeouts for the whole
run rather than one per step.

**R5 — Writer, proofreader, provenance.** The grounding ledger is the
canonical set of numbers executed steps produced. `enforce()` redacts the
offending *sentence* (not the paragraph) before compilation; `audit()` then
re-checks the compiled Markdown, ignoring structural lines and inline code
spans so session ids and config dumps are not mistaken for claims. The report
adds its own bookkeeping figures to the ledger explicitly — those are facts
about the run, produced by the run. PDF rendering is a *trusted* engine-authored
body that skips the AST gate (there is no untrusted author) but keeps the
sandbox, the deadline, and the `_params.json` discipline.

**R6 — Bridge & errors.** Eleven `research.*` methods, discovered through the
P0 seam. Blocking work runs via `asyncio.to_thread`; every expected failure
maps to `INVALID_PARAMS`. `research.stream` returns a `Stream` whose chunks are
`{event, cursor}` and whose final value is the session summary, and it always
terminates (terminal status, `follow=false`, or its own timeout).

**R7 — Tests & QA.** 103 new tests, all offline. Security coverage is
adversarial rather than illustrative: 17 distinct refusal cases for the code
gate, a lying backend whose invented figure is proven absent from the artifact,
a hanging backend proven not to stall the session, and a mid-run cancellation
proven terminal.

## Design decisions worth knowing

- **Every stage has a no-model path.** Not a stub — a real deterministic
  implementation. This is what makes the engine offline-capable *and* what
  makes a flaky provider a degradation instead of a failure.
- **A refused snippet is a self-correction signal.** The AST gate's reason goes
  back into the next codegen prompt, so the model learns the constraint inside
  the run rather than failing the section.
- **A failing section is a limitation, not a dead run.** The report says which
  section could not be concluded and why, in the Limitations list.
- **Autonomous ≠ more powerful.** Skipping the human checkpoint *removes*
  capability: no cleaning, no chart writes, read-only tools only.

## Known gaps / next

- Web search inside the loop is scaffolded (`allow_network` config, grant-set
  plumbing) but no network tool is wired in; P2 or a follow-up should add one
  behind the existing risk tiers.
- Sections run sequentially. The context and budget model already supports
  parallel per-section research; it was left serial to keep the sandbox
  contention story simple.
- `ReproducibilityExporter` is wired in and produces a ZIP when a provenance
  tracker is supplied; the bridge-level engine does not attach a tracker by
  default. P2 should pass the session's tracker through.
