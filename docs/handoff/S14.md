## Goal

Make the GitHub Release → NSIS → install → open Dream → use it path work on Windows
**without** the `v0.3.0` crash (already fixed in S13, on `main` at `b58a409`) and
**without** a separate `pip install`. The Windows installer must embed a CPython
runtime plus a non-editable Dream kernel so the shell's sidecar
(`python -u -m dream.bridge`) can start from a bare Release download.

## Facts driving this session

- `v0.3.0` / `Dream_0.3.0_x64-setup.exe` is the broken build (UI crash on
  `meta.dot`). S13 is on `main` (`b58a409`) but **no release contains S13**.
  `createUpdaterArtifacts` is false, so the installed exe never self-updates.
- The NSIS installer ships an empty `resources`/`externalBin`; the shell spawns
  `python`/`py`/`python3 -m dream.bridge`. A Release-only user cannot run it.
- `desktop-release.yml` already publishes a non-draft Release on `v*` tags. We
  do **not** retag `v0.3.0` or create `v0.3.1`; the owner tags after merge.
- Prefer **zero** `.github/workflows/**` edits (GitHub App may refuse them).
  Drive the Windows sidecar bundle from `tauri.conf.json` `beforeBuildCommand`.
