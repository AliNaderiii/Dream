## What shipped

- Standalone Telegram pairing remains private-chat-only, six-digit,
  single-use, ten-minute, and persistent. An explicit
  `TELEGRAM_ALLOWED_USER` remains the higher-priority owner allowlist and
  disables code pairing.
- Standalone replies/reminders now split at 4,000 characters instead of being
  truncated. A failed middle chunk resumes at that chunk without running the
  model again or duplicating the delivered prefix.
- Connectivity Telegram now ignores group/supergroup messages and advances a
  long-poll offset only after successful gateway handling.
- Connectivity Telegram delegates phone-safe slash commands to the CLI's
  existing allowlist. `/plan`, `/usage`, and `/route` work on phone, and
  `/help` lists the allowed command surface. Unknown slash commands are
  refused before reaching the model.
- Telegram and connectivity error/status/message-log boundaries redact bot
  tokens, common API keys, Bearer credentials, labelled credentials,
  credential environment values, and configured secret values.
- Dangerous tools remain fail-closed: no Telegram entry point configures an
  approver. A model request for `run_shell` is denied and causes no side
  effect.
- S00 already supplied the read-only commerce kernel used by `/plan` and
  `/usage`. S03 adds no checkout, purchase, payment, or other commerce flow.

## Owner-run live smoke checklist

> Run this manually after review. Do not paste the token into an issue, PR,
> test fixture, `.env` file, shell command argument, or CI secret for this
> smoke test. The automated suite uses fake transports only.

1. In Telegram, open the verified **@BotFather** account. Send `/newbot`, choose
   the bot name and username, and copy the BotFather token.
2. From the repository root, install the project if needed:

   ```bash
   python -m pip install -e '.[dev]'
   ```

3. Set the **actual environment variable** while keeping the token out of the
   command history. The silent prompt below stores it only in this shell's
   environment:

   ```bash
   read -rsp 'BotFather token: ' TELEGRAM_BOT_TOKEN && echo
   export TELEGRAM_BOT_TOKEN
   unset TELEGRAM_ALLOWED_USER
   ```

   To use a fixed owner allowlist instead of pairing, set the numeric Telegram
   user ID with `export TELEGRAM_ALLOWED_USER='123456789'`; do not do that for
   the pairing-code steps below, because an explicit allowlist intentionally
   disables pairing.

4. Start the standalone bot with the offline echo backend (Telegram transport
   is live, but no model provider receives the reminder text):

   ```bash
   dream-telegram --backend echo --db data/s03-live-smoke.db
   ```

5. Confirm the terminal prints a six-digit pairing code and a ten-minute
   expiry. Open a **private chat** with the new bot and send either the code or
   `/pair CODE`. Verify the bot confirms pairing. Try the same code from a
   second account/chat if available and verify it cannot be reused.
6. In the paired private chat, send this Persian reminder command exactly:

   ```text
   /remind فردا خرید نان
   ```

   Verify the bot confirms that the bread-shopping reminder was created.
7. Send `/help`. Verify the reply lists the allowed phone commands, including
   `/plan`, `/usage`, and `/route`. Send each of those three and verify each
   returns a non-empty read-only response.
8. Optional privacy check: add the bot to a test group and send `/help`; verify
   the group cannot access owner data or invoke the agent. Remove the bot from
   the group afterward.
9. Stop with `Ctrl-C`, remove the smoke database if it is not wanted, and clear
   the token from the shell:

   ```bash
   unset TELEGRAM_BOT_TOKEN
   ```
